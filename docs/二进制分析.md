## 节区特征

节区表中存在多个非常规节区名，例如 `DVCCK11`、`AgypD11`、`.A11`、`./sI`、`.>xE` 和 `.QZT`。其中 `.QZT` 的原始数据大小约为 `0xe21400`，熵值接近 `7.87`，明显接近压缩或加密数据的特征。

多个常规节区虽然有虚拟大小，但文件原始大小为 `0`。这意味着磁盘文件中的代码和数据并不是按照普通编译器输出方式保存，而是可能由加载器在运行时解包、映射或重建。本次源码解析器已把这些节区标记为“虚拟节区，磁盘无明文数据”。

## 导入表特征

导入表只暴露少量系统库和函数，例如：

- `KERNEL32.dll!WaitForSingleObject`
- `USER32.dll!ShowWindow`
- `ADVAPI32.dll!RegEnumKeyExA`
- `SHELL32.dll!SHGetFolderPathA`
- `ole32.dll!CoInitializeEx`
- `OLEAUT32.dll!序号导入 2`
- `WS2_32.dll!序号导入 16`
- `ntdll.dll!RtlLookupFunctionEntry`
- `IPHLPAPI.DLL!IcmpCreateFile`

这种导入表较小且不完整的情况，常见于加壳程序、加载器或经过保护的程序。真实业务逻辑需要在运行时解包后才能进一步确认。

## 对“Python 3.14 源码还原”的影响

当前样本未发现 `PYZ`、`PK`、`PyInstaller`、`Nuitka` 或 `.NET` 运行时目录等可以直接抽取源码/字节码的稳定结构。即使最终业务源项目使用 Python 3.14 编写，磁盘上的 `.exe` 也已被保护器改写，不能只靠静态文件直接恢复 `.py` 文件名、函数名和注释。

因此现阶段可靠产物是：

- 可在 Python 3.14 上运行的 `kk_recovered` 分析包；
- 已确认的 PE 元数据、导入表、资源表和保护证据；
- 为后续动态脱壳后迁移业务逻辑准备的源码工程骨架。
