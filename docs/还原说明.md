# 还原说明

## 目标

本项目的目标是在只有 `Z4B8T2N6.exe` 的情况下，建立一个可维护、可运行、可复现的源码还原工作区。所有说明文档均使用中文，避免后续维护者在还原过程、证据来源和限制条件之间产生歧义。

## 当前已完成内容

1. 保留原始可执行文件，避免破坏证据链。
2. 新增 `src/kk_recovered` 源码包，用 Python 标准库实现 PE 文件解析。
3. 新增命令行入口，可输出中文二进制分析报告。
4. 新增自动化测试，锁定已确认的关键字段，防止后续修改破坏解析能力。
5. 新增中文分析文档，记录当前能够从静态文件中确认的信息。

## 为什么没有直接提交“原作者源码”

`.exe` 是编译产物，编译过程中会丢失变量名、注释、模块边界和大量类型信息。如果文件还经过加壳、混淆或压缩，静态文件中看到的主要是壳代码和压缩数据，而不是原始业务逻辑。因此，可靠做法是先还原：

- 可复现的分析工具；
- 已验证的二进制事实；
- 可以持续补充的源码目录；
- 后续脱壳和动态分析路线。

## 后续建议

1. 在隔离的 Windows 虚拟机中运行样本，记录窗口、命令行输出、网络和文件行为。
2. 使用调试器在入口点之后跟踪解包过程，获取内存中的真实代码段。
3. 将内存转储重新构造成可分析 PE，再对真实业务函数做伪代码还原。
4. 将确认后的业务逻辑逐步迁移到 `src/kk_recovered`，并为每个行为补充测试。
