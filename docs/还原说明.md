# 还原说明

## 目标

本项目的目标是在只有 `Z4B8T2N6.exe` 的情况下，建立一个可维护、可运行、可复现的源码还原工作区。所有说明文档均使用中文，避免后续维护者在还原过程、证据来源和限制条件之间产生歧义。

用户运行环境为 Win10，Python 版本为 3.14；当前源码包不依赖第三方库，后续可以直接在该环境中运行。

## 当前已完成内容

1. 保留原始可执行文件，避免破坏证据链。
2. 新增 `src/kk_recovered` 源码包，用 Python 标准库实现 PE 文件解析。
3. 新增命令行入口，可输出中文二进制分析报告。
4. 新增 `pyproject.toml`，可在 Windows / Python 3.14 中以 `pip install -e .` 安装命令行脚本。
5. 新增资源表解析能力，可提取 `RT_MANIFEST` 应用清单。
6. 新增保护/加壳证据判断，自动提示虚拟节区、高熵节区、入口点节区、极小导入表和非 .NET 特征。
7. 新增自动化测试，锁定已确认的关键字段，防止后续修改破坏解析能力。
8. 新增中文分析文档，记录当前能够从静态文件中确认的信息。

## 为什么没有直接提交“原作者源码”

`.exe` 是编译产物，编译过程中会丢失变量名、注释、模块边界和大量类型信息。如果文件还经过加壳、混淆或压缩，静态文件中看到的主要是壳代码和压缩数据，而不是原始业务逻辑。

当前样本尤其明显：`.text`、`.rdata`、`.data`、`.pdata` 等常见节区的 `RawSize` 为 `0`，入口点落在高熵 `.QZT` 节区，导入表只有 9 个函数。这些证据说明原始业务逻辑大概率需要在运行时解包后从内存转储继续恢复。

因此，可靠做法是先还原：

- 可复现的分析工具；
- 已验证的二进制事实；
- 可以持续补充的源码目录；
- 后续脱壳和动态分析路线。

## 在 Win10 / Python 3.14 上运行

```powershell
py -3.14 -m pip install -e .
kk-recovered Z4B8T2N6.exe
```

如果不希望安装，也可以直接运行源码包：

```powershell
$env:PYTHONPATH = "src"
py -3.14 -m kk_recovered Z4B8T2N6.exe
```

## 后续建议

1. 在隔离的 Windows 10 虚拟机中运行样本，记录窗口、命令行输出、网络、注册表和文件行为。
2. 使用 x64dbg、Process Monitor、Process Explorer、TCPView/Wireshark 等工具记录运行时行为。
3. 在入口点之后跟踪 `.QZT` 解包过程，重点观察 `VirtualAlloc`、`VirtualProtect`、`WriteProcessMemory`、TLS 回调和内存页权限变化。
4. 程序稳定运行到真实入口后，转储内存中的 `.text`、`.rdata`、`.data` 和 `.pdata` 区域，并修复导入表。
5. 将内存转储重新构造成可分析 PE，再对真实业务函数做伪代码还原。
6. 将确认后的业务逻辑逐步迁移到 `src/kk_recovered`，并为每个行为补充测试。
