# KK 应用源码还原工作区

本仓库原始内容只有一个 Windows 可执行文件 `Z4B8T2N6.exe` 和占位文件 `kk`。本次提交在项目中补齐了可维护的源码还原工作区，用中文记录还原过程、已确认的二进制事实、可复现实验命令，以及一个可运行的 Python 分析入口。

> 说明：从已经打包、混淆或加壳的 `.exe` 中无法保证 100% 还原作者最初编写的源码。当前还原结果以“可验证证据 + 可运行源码 + 中文文档”的形式保存，便于后续继续脱壳、动态调试或替换为真实业务逻辑。

## 目录结构

| 路径 | 说明 |
| --- | --- |
| `Z4B8T2N6.exe` | 原始 Windows 可执行文件，作为还原输入保留。 |
| `src/kk_recovered/` | 已还原出的可运行源码包，提供 PE 文件解析和中文报告输出。 |
| `tests/` | 针对源码包的自动化测试，验证关键 PE 字段解析结果。 |
| `docs/` | 中文还原文档，记录证据、限制和后续路线。 |

## 快速运行

```bash
PYTHONPATH=src python3 -m kk_recovered Z4B8T2N6.exe
```

运行后会输出中文分析报告，包括文件大小、架构、子系统、入口点、节区、导入表和资源表等信息。

## 自动化检查

```bash
python3 -m pytest -q
```

如果环境没有安装 `pytest`，可以先使用标准库入口做基础验证：

```bash
PYTHONPATH=src python3 -m kk_recovered Z4B8T2N6.exe
```

## 还原结论摘要

- 文件头为 `MZ`，属于 PE32+ x86-64 Windows 控制台程序。
- 节区表显示大部分原始节区在文件中的 `raw size` 为 `0`，实际数据集中在高熵 `.QZT` 节区中。
- 导入表只保留了少量 API，符合“壳加载器/保护器”常见特征。
- 因此当前项目先还原出可运行的分析源码和证据文档，后续若获得脱壳内存转储或原始符号，可继续替换为真实业务源码。
