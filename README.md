# KK 应用源码还原工作区

本仓库围绕 `Z4B8T2N6.exe` 持续还原项目源码。由于厂商 VPS 已销毁，目前只能从 Windows 可执行文件反推可验证的结构、运行约束与后续脱壳入口；本次继续补齐了更完整的 PE 静态解析能力、资源清单提取、保护器证据判断和可安装的 Python 源码工程骨架。

> 说明：从已经打包、混淆或加壳的 `.exe` 中无法保证 100% 还原作者最初编写的源码。当前还原结果以“可验证证据 + 可运行源码 + 中文文档”的形式保存，便于后续在 Win10 / Python 3.14 环境中继续脱壳、动态调试或替换为真实业务逻辑。

## 目录结构

| 路径 | 说明 |
| --- | --- |
| `Z4B8T2N6.exe` | 原始 Windows 可执行文件，作为还原输入保留。 |
| `src/kk_recovered/` | 已还原出的可运行源码包，提供 PE 文件解析、资源解析和中文报告输出。 |
| `tests/` | 针对源码包的自动化测试，验证关键 PE 字段、资源清单和保护器证据。 |
| `docs/` | 中文还原文档，记录证据、限制和后续路线。 |
| `pe_static_report.py` | 初始静态报告脚本，保留用于交叉验证。 |

## 快速运行

无需第三方依赖，可直接用源码目录运行：

```bash
PYTHONPATH=src python3 -m kk_recovered Z4B8T2N6.exe
```

也可以在 Windows / Python 3.14 中以可编辑模式安装后运行命令行入口：

```powershell
py -3.14 -m pip install -e .
kk-recovered Z4B8T2N6.exe
```

运行后会输出中文分析报告，包括文件大小、SHA-256、时间戳、架构、子系统、入口点、节区、数据目录、导入表、资源表、应用清单和保护/加壳证据。

## 自动化检查

```bash
python3 -m pytest
```

如果环境没有安装 `pytest`，可以先使用标准库入口做基础验证：

```bash
PYTHONPATH=src python3 -m kk_recovered Z4B8T2N6.exe
```

## 当前还原结论摘要

- 文件头为 `MZ`，属于 PE32+ x86-64 Windows 控制台程序。
- COFF 时间戳为 `2026-05-30T09:06:19+00:00`，样本 SHA-256 为 `9465eabafbdb8c4be0d301755dab5187e068fa3caf97a2ce57bd60ccfa8f3b30`。
- 节区表显示 `.text`、`.rdata`、`.data`、`.pdata` 等 9 个节区在文件中的 `RawSize = 0`，实际数据集中在高熵 `.QZT` 节区中。
- 入口点落在 `.QZT` 高熵节区，导入表只有 9 个函数，符合“壳加载器/保护器”常见特征。
- 资源表只有一个 `RT_MANIFEST` 应用清单，权限级别为 `asInvoker`，未发现 `.NET` 运行时目录。
- 因此当前项目先还原出可运行的分析源码和证据文档；后续若获得脱壳内存转储或原始符号，可继续替换为真实业务源码。
